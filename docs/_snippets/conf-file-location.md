The packaged service starts `xrpld` with `--conf /etc/xrpld/xrpld.cfg`, so that is the config file the [recommended installation](../infrastructure/installation/index.md) uses. If you start `xrpld` yourself without `--conf`, it looks in the current working directory, then in `$XDG_CONFIG_HOME/xrpld/xrpld.cfg` (with `$HOME/.config` standing in when `$XDG_CONFIG_HOME` isn't set, for the user running `xrpld`), then in `/etc/xrpld`.

The config file was renamed from `rippled.cfg` to `xrpld.cfg`. During the transition, if you start `xrpld` without `--conf` and `xrpld.cfg` is not present, the server still reads `rippled.cfg` from those same directories; a config left at the old `/etc/opt/ripple` path is not read. The packaged service passes `--conf`, so it reads only `/etc/xrpld/xrpld.cfg`; copy an old config to that name (see [Migrate from rippled to xrpld](../infrastructure/installation/migrate-to-xrpld.md)). {% badge href="https://xrpl.org/blog/2026/xrpld-3.2.0" %}Updated in: rippled 3.2.0{% /badge %}
