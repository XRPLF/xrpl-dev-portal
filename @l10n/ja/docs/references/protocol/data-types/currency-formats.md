# 通貨フォーマット

XRP Ledgerには、XRP、[トークン](../../../concepts/tokens/index.md)、[Multi-Purpose Token（MPT）](../../../concepts/tokens/fungible-tokens/multi-purpose-tokens.md)の3種類のデジタル資産があります。これらのフォーマットは異なりますが、3種類とも高い精度を持ちます。

{% amendment-disclaimer name="MPTokensV1" /%}

## 比較

以下の表は、XRP LedgerにおけるXRP、トークン、MPTの違いの一部をまとめたものです。

| XRP                                                      | トークン |  MPT |
|:---------------------------------------------------------|:------------------|:---------------------|
| 発行者は存在しません。                                       | 常にXRP Ledgerのアカウントが発行します。 | 常にXRP Ledgerのアカウントが発行します。 |
| 文字列形式で指定します。                                     | オブジェクト形式で指定します。 | オブジェクト形式で指定します。 |
| [アカウント](../ledger-data/ledger-entry-types/accountroot.md)に記録されます。 | [トラストライン](../ledger-data/ledger-entry-types/ripplestate.md)に記録されます。 | 保有者のアカウントに記録されます。 |
| 新たに作成することはできず、破棄することしかできません。         | 自由に発行・償還できます。 | 自由に発行・償還できます。 |
| 最小値: `0`（負の値にはなりません。）                         | 最小値: `-9999999999999999e80`。ゼロでない絶対値の最小値: `1000000000000000e-96`。 | 最小値: `0`（負の値にはなりません。） |
| 最大値: `100000000000`（10<sup>11</sup>）XRP。これは`100000000000000000`（10<sup>17</sup>）dropです。 | 最大値: `9999999999999999e80`。 | 最大値: `0x7FFFFFFFFFFFFFFF`。 |
| 1 drop（0.000001 XRP）単位の精度です。                        | 10進数で15桁の精度です。 |
| [フリーズ](../../../concepts/tokens/fungible-tokens/freezes.md)できません。 | 発行者は残高を[フリーズ](../../../concepts/tokens/fungible-tokens/freezes.md)できます。 | 発行者は残高を個別に、または全体的にロックできます。 |
| 送金手数料はかかりません。XRP同士の支払いは常に直接行われます。 | 間接的な[パス](../../../concepts/tokens/fungible-tokens/paths.md)を経由でき、各発行者は一定割合の[送金手数料](../../../concepts/tokens/fungible-tokens/transfer-fees.md)を請求できます。 | トークンの二次販売に対して送金手数料を請求できます。 |
| [ペイメントチャネル](../../../concepts/payment-types/payment-channels.md)と[エスクロー](../../../concepts/payment-types/escrow.md)で使用できます。 | ペイメントチャネルやエスクローには対応していません。 | ペイメントチャネルやエスクローには対応していません。 |

詳細は、[XRPとは?](../../../introduction/what-is-xrp.md)、[トークン](../../../concepts/tokens/index.md)、[Multi-Purpose Token](../../../concepts/tokens/fungible-tokens/multi-purpose-tokens.md)を参照してください。

## 通貨額の指定

指定する通貨の種類に合ったフォーマットを使用してください。

- [XRPの金額](#xrpの金額)
- [トークンの金額](#トークンの金額)
- [MPTの金額](#mptの金額)

### XRPの金額

XRPの金額を指定するには、XRPの _drop_ 数を表す[文字列フォーマット][]の数値を使用します。1 dropは0.000001 XRPに相当します。たとえば、13.1 XRPを指定するには次のように書きます。

```
"13100000"
```

**XRPをオブジェクト形式で指定しないでください。**

XRPの金額は負になることはありません。

### トークンの金額

[（代替可能）トークン](../../../concepts/tokens/index.md)の金額を指定するには、`Amount`オブジェクトを使用します。トークンでは、`currency`、`value`、`issuer`の各フィールドを使用します。

| `Field`    | 型                    | 説明                        |
|:-----------|:---------------------|:-----------------------------------|
| `currency` | 文字列 - [通貨コード][] | トークンの任意の通貨コード。`XRP`は使用できません。 |
| `value`    | [文字列フォーマット][]  | トークンの金額を10進数で表した、引用符で囲まれた文字列。`1.23e11`（123,000,000,000を意味します）のような科学的記数法も使用でき、`e`と`E`のどちらも使用できます。残高を表示する場合は負の値になることがありますが、送金額を指定する場合など、それ以外の場面では負の値は使用できません。 |
| `issuer`   | 文字列                | 通常は、このトークンを発行する[アカウント](../../../concepts/accounts/index.md)です。特殊なケースでは、代わりにトークンを保有しているアカウントを指すことがあります（例: [Clawback](../transactions/types/clawback.md)トランザクション）。 |

[文字列フォーマット]: #文字列フォーマット

{% admonition type="warning" name="注意" %}これらのフィールド名は大文字と小文字を区別します。{% /admonition %}

たとえば、アカウント`r9cZA1mLK5R5Am25ArfXFmqgNwjZgnfk59`が発行した153.75 USドルを表すには、次のように指定します。

```json
{
    "currency": "USD",
    "value": "153.75",
    "issuer": "r9cZA1mLK5R5Am25ArfXFmqgNwjZgnfk59"
}
```

### MPTの金額

MPTの金額は`value`フィールドで指定します。

| `Field`    | 型                    | 説明                        |
|:-----------|:---------------------|:-----------------------------------|
| `mpt_issuance_id` | 文字列         | Multi-Purpose Tokenを一意に識別する任意の識別子。 |
| `value`    | [文字列フォーマット][]  | 正の整数値を表す文字列。有効な値は0x0以上0x7FFFFFFFFFFFFFFF以下です。MPTの値の端数を表すには`AssetScale`を使用します。[MPTの精度](#mptの精度)を参照してください。 |

たとえば、MPTを100万単位指定するには、次のように指定します。

```json
{
    "mpt_issuance_id": 
	     "0000012FFD9EE5DA93AC614B4DB94D7E0FCE415CA51BED47",
    "value": "1000000"
}
```


### 金額なしでの通貨の指定

[分散型取引所](../../../concepts/tokens/decentralized-exchange/index.md)のオーダーブックを指定する場合など、特定の金額を指定せずに資産（XRPやトークン）を定義する必要があることがあります。

金額なしでトークンを記述するには、通貨オブジェクトとして指定し、`value`フィールドを省略します。例:

```json
{
  "currency": "TST",
  "issuer": "rP9jPyP5kyvFRb6ZiRghAGw5u8SGAmU4bd"
}
```

金額なしでXRPを記述するには、`currency`フィールド _のみ_ を持つJSONオブジェクトとして指定します。XRPには`issuer`フィールドを含めないでください。例:

```json
{
  "currency": "XRP"
}
```

金額なしでMPTを記述するには、`mpt_issuance_id`フィールド _のみ_ を持つJSONオブジェクトとして指定します。例:

```json
{
  "mpt_issuance_id": "0000012FFD9EE5DA93AC614B4DB94D7E0FCE415CA51BED47"
}
```

## XRPの精度

XRPは64ビットの符号なし整数と同じ精度を持ち、各単位は0.000001 XRPに相当します。XRPは整数計算を使用するため、1 dropに満たない金額は切り捨てられます。

## トークンの精度

トークンは、一般的に非常に小さい単位や非常に大きい単位で取引されるものを含め、さまざまな資産を表すことができます。このフォーマットは、科学的記数法と同様に、有効数字と10の累乗の指数を使用します。指定された範囲内であれば、有効数字と指数のどちらも正負の値をサポートしています。整数でない数の一般的な浮動小数点表現とは異なり、このフォーマットはすべての計算に整数演算を使用するため、常に10進数で15桁の精度を維持します。乗算と除算では、最下位桁での過剰な丸めを補正するための調整が行われます。

XRP Ledgerのピアツーピアネットワークでトークンの金額を送信する場合、サーバは金額を64ビットのバイナリ値に[シリアライズ](../binary-format.md)します。

{% admonition type="success" name="ヒント" %}まったく分割できないトークンについては、[非代替性トークン（NFT）](../../../concepts/tokens/nfts/index.md)を参照してください。{% /admonition %}

## MPTの精度

MPTは常に整数で表されます。MPTの`AssetScale`を変更すると、基本単位をMPTの端数として表すことができます。XRP Ledgerはオンチェーンで`AssetScale`を使用しません。これは基本単位を指定する際の利便性のためのものです。

たとえば、13.1 MPTという値を表すには、MPTの`AssetScale`を1に設定し、MPTの`value`を131に設定する必要があります。

```json
   "Amount": {
      "mpt_issuance_id":
        "0000012FFD9EE5DA93AC614B4DB94D7E0FCE415CA51BED47",
      "value": "131"
    }
```

### 標準通貨コード

通貨コードの標準フォーマットは`USD`のような3文字の文字列です。これは[ISO 4217 Currency Codes](https://www.xe.com/iso4217.php)で使用することを想定しています。以下のルールがあります。

- 通貨コードの長さはちょうど3文字のASCII文字でなければなりません。使用できる文字は、すべての大文字と小文字、数字、および記号`?`、`!`、`@`、`#`、`$`、`%`、`^`、`&`、`*`、`<`、`>`、`(`、`)`、`{`、`}`、`[`、`]`、<code>&#124;</code>です。
- 通貨コードは大文字と小文字を区別します。
- 通貨コード`XRP`（すべて大文字）は使用できません。本来のXRPは、通常、XRP Ledgerプロトコルでは通貨コードを使用しません。

プロトコルレベルでは、このフォーマットは`0x00`で始まる160ビットのバイナリ値に[シリアライズ](../binary-format.md#通貨コード)されます。

### 非標準通貨コード

160ビット（40文字）の16進文字列を通貨コードとして使用することもできます。例:
`444F4C4C415259444F4F00000000000000000000`

トークン`RLUSD`は次のように表されます。

 `524C555344000000000000000000000000000000`

TrustSetトランザクションやPaymentトランザクションを作成する場合は、`currency`フィールドに16進数の値を使用してください。

#### 非標準通貨コードに関する注意事項

非標準通貨コードを使用したり読み取ったりする場合は、次の点に注意してください。

- 通貨コードを読み取るほとんどのインターフェースは、可能であれば非標準コードをASCIIに変換します。
- すべての16進数の通貨コードに、人が読める表現があるわけではありません。[Normalize Currency Codes](https://github.com/XRPLF/xrpl-dev-portal/tree/master/_code-samples/normalize-currency-codes)を参照してください。
- 非標準通貨コードをASCIIまたはUTF-8としてデコードすると、表示時に印字されない文字や、マークアップとして解釈される文字が含まれる場合があります。
- XRPや別の資産のように表示されても、実際には異なる通貨を表す「なりすまし」の通貨コードに注意してください。

一部のAPIとの互換性のため、非標準通貨コードの最初の8ビットは`0x00`で始めないでください（SHOULD NOT）。プロトコルレベルでは、非標準通貨コードは`0x00`で始めることも _できます_ が、一部のAPIでは`0x00`で始まるコードを標準通貨コードとして解釈し、正しく処理できない場合があります。

**廃止予定:** 一部の旧バージョンの[ripple-lib](https://github.com/XRPLF/xrpl.js)では、`015841551A748AD2C1F76FF6ECB0CCCD00000000`のような「有利子」または「マイナス利子」の通貨コードタイプがサポートされていました。これらのコードの先頭8ビットは`0x01`です。マイナス利子または有利子の通貨はサポートされなくなりましたが、過去のレジャーデータに現れることがあります。詳細は、[マイナス利子](../../../concepts/tokens/fungible-tokens/demurrage.md)を参照してください。
